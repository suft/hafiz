# Play Console guide

Everything the Play Console asks for that fastlane metadata (`metadata/android/*/`) cannot hold. Upload is manual.

## 1. Before the first upload

- [ ] Back up `release.jks` and the keystore password from `keystore.properties` somewhere outside the repo. This is the upload key; losing it means a key-reset request to Google. `~/hafiz-old-keys/` holds the retired "Ayah Surah" key; delete it once the new key is backed up.
- [ ] Review the pairs in `tools/mutashabihat_supplement.txt`.
- [ ] Push the repo to `github.com/suft/hafiz`: `git remote add origin git@github.com:suft/hafiz.git && git push -u origin main`.
- [ ] Enable Pages: Settings → Pages → Deploy from a branch → `main` / `/docs`.
- [ ] Check that `https://suft.github.io/hafiz/privacy-policy.html` loads.
- [ ] On the day you submit for review, set the effective date at the top of `docs/privacy-policy.md` in both languages (`Effective <d Month yyyy>` and `تاريخ السريان: <same date in Arabic-Indic digits and Arabic month name>`) to the day Pages serves it, then push.
- [ ] Add repository secrets (Settings → Secrets and variables → Actions): `HAFIZ_KEYSTORE_BASE64` (output of `base64 -w0 release.jks`), `HAFIZ_KEYSTORE_PASSWORD`, `HAFIZ_KEY_ALIAS` (`hafiz`), `HAFIZ_KEY_PASSWORD`.

## 2. Create the app

- App name: from `title.txt`.
- Default language: English (United States) – `en-US`.
- App or game: **Game**.
- Free.
- Accept the declarations.

## 3. App signing

Use Play App Signing with a Google-generated app-signing key. `release.jks` (alias `hafiz`) is the upload key.

## 4. Store listing

Grow → Store presence → Main store listing.

- Paste `en-US/*` into the default listing. Add the translations from `ar/*`, `de-DE/*`, `es-ES/*`, `fr-FR/*`, `it-IT/*` and `pt-BR/*`. Only `en-US` and `ar` have graphics and screenshots; Play shows the default (en-US) ones for the other translations.
- Category: Game → **Educational**.
- Contact email `sufientout@gmail.com`; website `https://github.com/suft/hafiz`.
- Icon and feature graphic: upload each locale's `images/icon.png` and `featureGraphic.png` (`en-US` for the default listing, `ar` for the Arabic translation; the files are identical). Regenerate them with `mise run store-graphics`.
- Phone screenshots:
  - Generated by `mise run screenshots` (debug build on a headless 1080×1920 emulator, light theme, demo status bar, seeded statistics): (1) main menu, (2) a Guess the Surah question, (3) a Where's the Ayah? question, (4) Statistics → Surahs tab, (5) the load screen, (6) the Credits overlay, Arabic in `ar/images/phoneScreenshots/` and English in `en-US/images/phoneScreenshots/`. Upload each locale's six.
  - Play needs 2–8 screenshots, PNG or JPEG, sides 320–3840 px, long side at most twice the short side (1080×2400 is rejected). Follow the console if it says otherwise.

## 5. App content

Policy → App content.

- Privacy policy: `https://suft.github.io/hafiz/privacy-policy.html`.
- Ads: No.
- App access: all functionality is available without special access.
- Content rating (IARC):
  - Category: Game.
  - Answer No to violence, fear, sexuality, language, controlled substances, crude humour, gambling and simulated gambling.
  - Answer No to user interaction or chat, sharing users' location, digital purchases, and unrestricted internet browsing. Sharing a score through Android's share sheet is not in-app user interaction.
  - Expected result: Everyone / PEGI 3 / USK 0.
- Target audience: ages 13–15, 16–17 and 18+. Not designed for children, so the Families policy doesn't apply. Appeals to children: No.
- News app: No. Government app: No. Financial features: none. Health: none.

### Data safety

- "Does your app collect or share any of the required user data types?" **No**. So no data types are declared.
- Reasons:
  - Progress and settings never leave the device except through Android's own backup, which Play does not count as developer collection.
  - Audio requests to everyayah.com fetch public files; like any HTTPS request they carry the IP address and a fixed User-Agent ("Hafiz-Android"), and no user data. The developer runs no server and receives nothing.

## 6. Testing and release

- Run `mise run check && mise run bundle`. Upload `dist/Hafiz-release.aab` to **Internal testing** first and install it from the tester link.
- Personal developer accounts must run a **Closed testing** track with at least 12 opted-in testers for 14 continuous days before applying for production. Follow whatever Play Console's Dashboard shows.
- Then go to **Production**. Countries: all. Release notes come from `changelogs/<versionCode>.txt`.

## 7. Every later release

- Bump `versionCode` (+1) and `versionName` in `app/build.gradle.kts`.
- Add `changelogs/<versionCode>.txt` in every locale.
- Run `mise run check && mise run bundle`, then upload. Play rejects a reused `versionCode`.
- Tag and push `v<versionName>` (`git tag v1.1 && git push origin v1.1`): the release workflow attaches the signed APK and AAB to a GitHub Release. Upload the AAB to Play by hand.
